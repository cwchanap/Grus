## Architecture: reuse existing contracts

- Rust's `building_view_transform` owns position at **footprint center** and root scale **(width, 1, height)**. Godot's fixed orthographic `Camera3D` in `main.tscn` is pitched **−54°** toward north (−z), with no rotation mechanics. The Rust bridge's value-gated `set_state(complete, cold)` and metadata order remain unchanged.
- `godot/scripts/building_view.gd` retains one `Model` child, early state caching, one completion swap, attachment retries, the existing `HealthBar` and `set_health_ratio`, and the `building_views` group/metadata. Use an explicit **eight-texture preload map**, one site texture and the existing Wall/Gate GLB PackedScenes; keep the visible unknown-kind fallback.
- For a painted kind, construct a `Model` wrapper with inverse horizontal scaling `(1/width, 1, 1/height)` to cancel the Rust root's nonuniform X/Z scales; the effective sprite must stay square and **width world units wide**, with `pixel_size = width / texture_width` (all nine sources square). Do not hardcode footprint sizes per kind. For the two mesh kinds keep their normal GLB model transform.
- **Pin the view-ray depth, not merely the on-screen position:** rotate the Sprite3D **−54° about X**, with billboard disabled; place its **bottom image edge at the camera-side (+z) edge** of the authoritative footprint, with bottom y approximately ground +0.01 to avoid z-fighting. With quad world width `w`, square image and a centered sprite, the quad center in post-compensation/world-relative coordinates is approximately `y = 0.5 × w × cos(54°) + 0.01` and `z = (footprint_depth / 2) − 0.5 × w × sin(54°)`. The image plane runs toward −z as it rises. Evaluate image alpha padding/ground contact in screenshots; do not compensate by changing the Rust transform.
- The last rule is a **starting geometry contract**, not a proof that every unit/art outline is never occluded incorrectly. Verify at default and zoom-out camera sizes, including Worker and tall aliens behind/near buildings. Keep actual depth testing; no CanvasLayer, `no_depth_test`, always-on-top or shader framework. Explicitly set `Sprite3D.cast_shadow = GeometryInstance3D.SHADOW_CASTING_SETTING_OFF`: the painted PNG already contains its contact shadow, and the sun's 3D shadow must not add a detached cardboard silhouette. Finished Wall/Gate GLBs retain normal 3D shadows.

## Texture import and shading

Commit corresponding PNG `.import` files with `mipmaps/generate=true`, `compress/mode=0` (Lossless), `detect_3d/compress_to=0` (prevent reimport flipping back to VRAM compression). Runtime audit verifies texture mipmaps, alpha and CPU-readable image, plus that the texture matches the imported source. Default `Sprite3D.texture_filter=LINEAR_WITH_MIPMAPS` and `fixed_size=false`. Use `shaded=false` to preserve painted colors.

Start with `ALPHA_CUT_OPAQUE_PREPASS` to retain translucent contact shadow/soft edges while giving opaque pixels depth; compare against `ALPHA_CUT_DISCARD` on the real Compatibility renderer if necessary. Preserve contact shadow and thin crystal/smokestack at the default 54-size camera and zoom-out. Don't claim the alpha-mode choice is verified until captured pixels demonstrate correct silhouettes, near/far occlusion, and absence of obvious hard fringes/shimmer. Godot 4.7 API refs: [SpriteBase3D](https://docs.godotengine.org/en/4.7/classes/class_spritebase3d.html), [BitMap](https://docs.godotengine.org/en/4.7/classes/class_bitmap.html), [texture imports](https://docs.godotengine.org/en/4.7/tutorials/assets_pipeline/importing_images.html).

Rust already restricts cold to complete Team-1 heat-consuming buildings; Wall, Gate and CoalFurnace never receive cold. Reuse `Sprite3D.modulate` for a subtle reversible icy tint; warm returns to `Color.WHITE`. Do not mutate PNG resources. No GLB icy overlay remains needed; delete `ice_overlay.tres` and its obsolete mesh application path after removing consumers. The `HealthBar` seats **above the top center of the visually opaque painted artwork**, not at the full texture/quad top or the raw `Image.get_used_rect()` (near-transparent halo pixels skew that boundary). **Reuse one per-texture thresholded `BitMap` cache** (e.g. a small static dictionary/function on `building_view.gd`, shared with `battlefield_controller.gd`) for both alpha hit-testing and the first opaque row / center-column used for HP placement; start with `create_from_image_alpha(image, 0.1)` and verify the chosen threshold against the real artwork. Convert the chosen sprite-local top point into the direct `BuildingView` child's local coordinates using `global_transform.affine_inverse() * sprite.global_transform * local_top`, then offset +0.15 on local Y to clear the sprite plane. Do **not** write sprite world-space Z/Y directly to `HealthBar.position` because the BuildingView root scales X/Z by the footprint (up to 4×). Finished Wall/Gate keep mesh AABB-based bar placement.

## Picking and visibility without a parallel subsystem

- Reuse `battlefield_controller.gd::_building_at`, `_projected_art_rect`, `_view_art_bounds` and `_model_ray_hit_depth`. For bounds and health-bar seating, widen the current `MeshInstance3D` child filters to **`GeometryInstance3D`**, checking that children are `MeshInstance3D` or `SpriteBase3D` with valid visible geometry. Both expose `get_aabb()`. Scope to `Model`, excluding the sibling `HealthBar`; preserve the cache invalidation that naturally occurs when `Model` swaps.
- For painted sprites, reuse `SpriteBase3D.generate_triangle_mesh().intersect_ray` in the existing ray path to obtain depth comparable to the GLB triangle path; transform the hit to sprite-local pixels using `get_item_rect()` and `pixel_size`, **flip local hit Y into top-down image-row coordinates**, and confirm an opaque texel using the **same per-texture thresholded BitMap cache** used to seat the health bar (`get_bitv(Vector2i)`). Transparent corners must not count as a hit. Keep the existing GLB mesh-triangle branch; do not write a separate general ray-plane engine.
- Preserve the current **20px center-radius fallback only for near misses / unstyled views** and all fog/team filtering; ensure it never converts a transparent-corner hit away from the center into an opaque-art hit. Keep unit/resource selection and unit-only drag box selection unchanged.
- Pre-existing overlap bug: `_select_at` picks units within 20px before buildings, and `_nearest_enemy_view` compares projected center distances only. Refactor only the existing building hit path into `_building_hit_at(screen_position, team_filter) -> Dictionary` with `{view, depth}` (use `depth = INF` for a **20px fallback-only** hit); keep `_building_at` as a thin view-returning wrapper. For an overlapping candidate unit, only let the building override it if a **real opaque silhouette** hit has `depth < INF` and `depth < (unit.global_position + Vector3(0, 0.15, 0) - ray_origin).dot(ray_direction)`. The small Y offset avoids a completed Gate's low plinth stealing clicks on a Worker passing through its corridor; testing a tall Behemoth behind a painted building prevents using the unit's full height as the comparison. Fallback hits must not steal unit clicks. Apply the same narrow rule to right-click enemy target comparison, preserve nonoverlapping picks, fog/team constraints and unit-only drag-box selection; do not introduce arbitrary unit-mesh raycasts or a generic hit registry.

## Tests, captures, acceptance

The existing Godot smokes drive real input and already cover startup/reset, economy & construction, cold/furnace recovery, turret combat, Wall/Gate, waves and underground. **Sprite rendering and sprite-aware picking belong in the same first checkpoint**: otherwise existing live roof picking and transparent-corner smokes fail. Update representation assertions **as each feature changes**, including `reset_test.gd`, `_roof_pick_point`, `_radius_steal_pick_point`, and the old horizontal-ray/height-based site→Depot swap probe in `smoke_test.gd` (replace with actual texture/Model swap + camera-ray alpha assertion). In `economy_smoke_test.gd::_overlay_is`, check Sprite3D `modulate` for painted buildings and the **no-cold** 3D GLB behavior for completed Wall/Gate; the existing tests exercise both. Keep gameplay, lifecycle, cold and construction checks intact; extend source/texture/import audits without auditing dead GLBs. Reuse `SmokeHelpers.view_art_error` with `GeometryInstance3D` bounds. Preserve the existing `SMOKE_STRUCTURE_AUDIT source_bytes=editor` marker when narrowing the structure audit: `.github/workflows/ci.yml` requires that exact output.

Use existing `GRUS_CAPTURE_DIR` and `SmokeHelpers.capture_frame` inside the smokes to capture **real 1280×720 frames** at startup, site in progress, cold and restored warm, and behind/in-front unit overlap at default/zoomed framing. Run the seven existing native smokes and real-renderer captures using their **standard Godot CLI/CI commands**, not an invented MCP test runner. For **end-to-end acceptance**, MCP reviews the runnable journey results, actual screenshots and UI against the ticket's **right-hand mockup** on one native platform; record observations and test evidence, not a synthetic screenshot oracle. Deterministic pass/fail remains with CLI/CI exit codes, smoke assertions and preserved CI markers. No separate duplicate journey and no human acceptance criterion.

Merging requires: all nine correct (HPA-1146 updated) runtime PNGs, eight correct finished kinds, shared site even for incomplete Wall/Gate, finished Wall/Gate GLBs and corridor tests, opaque-pixel clicking, depth ordering, correct cold/HP display, all seven smoke journeys, exported-build e2e and hosted CI green, and recorded screenshot evidence.
