**Status:** Planning only. This draft is **the implementation PR**; do not open a second PR for this issue.

## Why now / existing code survey

- HPA-445, HPA-448 and HPA-449's code are merged. HPA-450 is the next step in the eight-ticket chain; its subsequent heat task (HPA-181) remains blocked until this is complete. Linear HPA-449 is Done.
- `catalog.rs` has four building kinds, `BuildingSpec` without combat, and `CombatSpec` on units. Extend, do not duplicate.
- `map.rs` is a single `GridMap { blocked, revision }`, with free-cell `is_walkable` and team-agnostic `find_path`. `movement.rs` checks `is_walkable` on candidate/separation cells. Route creators live in `commands.rs`, `combat.rs`, `buildings.rs` and economy helpers.
- `buildings.rs` already validates preview with the post-placement map, spends atomically, assigns one builder, and completes sites. `step_construction(world, seconds)` currently makes the Worker Idle on completion.
- `combat.rs` already holds `CombatTarget::{Unit,Building}`, shared acquisition, cooldown/hit/destruction and Crystal kill rewards. `CombatEvent.attacker` is currently `UnitId`; reuse existing `CombatTarget` on the attacker side **instead of introducing an identical enum**. `grus-godot/src/lib.rs` scrubs invisible attacker identities and serializes target kind/ID; `battlefield_controller.gd` resolves a unit view for tracers.
- `battlefield_controller.gd::_try_placement` always disarms after successful placement; `_unhandled_input` currently lets right-click continue to context commands.
- Reuse existing Godot building placeholder and `CombatFx`. No asset-generation work in this issue; separate existing tickets own art and SFX.

## Reviewable implementation stages (one PR)

These stages are commits/checkpoints on **this PR**, not additional issues or PRs. Preserve existing green tests between stages where practical.

### 1. Catalogue and GridMap contract

**Files:** `crates/grus-sim/src/catalog.rs`, `map.rs`, `map/tests.rs`, `catalog/tests.rs` and direct call sites.

- Add Wall/Gate/GunTurret catalogue entries and one optional building combat spec. Keep all numeric tuning in `catalog.rs`. Use the design's provisional values for unspecified turret/build times, adjusting within this PR if tests/game feel warrant it.
- Pin `GridMap` to existing `blocked` cells **plus a `gates` subset flag set**; do not create a parallel grid. Keep `is_walkable` unchanged for all free-ground checks. Add `is_traversable_for(team, cell) = is_walkable(cell) || (team == TeamId(1) && gates.contains(cell))`, and update `find_path` to take `TeamId` directly. **Guard A* start with team-aware traversal** (Team-1 may replan while standing on Gate, Team-2 may not); guard A* goal with **free-ground `is_walkable` for both teams**, and apply team-aware traversal to neighbor expansion. Gates are allowed intermediate Team-1 waypoints but never assigned goals. Clone `gates` in `GridMap::clone`; `set_blocked(cell, false)` clears it. On valid placement, set blocked+gate flag for the same cell **once**, bumping the one map revision once; no completion-time map transition.
- Compile-error audit `find_path(`, `is_walkable(` inside movement routes, `set_blocked(` and all building destruction/reset paths. Keep non-movement checks (placement, gather slots, spawn slots, free-cell preview) team-agnostic.
- Sim tests: Wall/Gate **sites** already claim occupancy at placement; Team-1 path **starting on a Gate site** succeeds, Team-2 path starting on it fails, **a Gate goal fails for both teams**, and Team-1 traverses a Gate site or completed Gate as an intermediate cell. Both blocked by Wall; revision increments only on real occupancy change, no route crosses alien-facing Gate; destruction clears both blocked+gate flag and restores routes; no extra Gate completion revision.

### 2. Gate-aware path/movement consumers and placement

**Files:** `commands.rs`, `movement.rs`, `buildings.rs`, `economy.rs` and any other compiler-discovered path consumers, with targeted tests.

- Thread the existing mover `TeamId` through A*, movement arrival/separation, forced and revision-triggered replans, AttackMove, pursuit, worker gather/dropoff and construction travel. Do not convert the placement/spawn free-cell predicates to mover-aware checks.
- Keep the existing `validate_placement` clone/post-footprint reachability flow; for a Gate site, put its **blocked+gate flags into the cloned map before the human builder's reachability probe**. Commit the same flags atomically with successful placement, never on completion. This preserves human traversal from the first tick without changing construction-completion map mutability. Retain existing free-ground checks, spend/occupancy/worker retask ordering and shared `set_blocked(false)` destruction release.
- Tests: accepted and rejected routes retain previous orders correctly; a Worker walks through a newly placed Gate; an alien cannot, even when the route was assigned before placement; placement overlap remains illegal; constructing or destroying a Gate changes route revision and recovers orders.

### 3. One shared strike path, turret acquisition and event bridge

**Files:** `combat.rs` and tests, `catalog.rs`, `crates/grus-godot/src/lib.rs`, `godot/scripts/{battlefield_controller,combat_fx}.gd`.

- Reuse **`CombatTarget` as the attacker stable identity**: change `CombatEvent.attacker: UnitId` to `CombatTarget`, rather than introducing `CombatAttacker`. Refactor `strike` to accept attacker context (entity, team, combat spec) but keep exactly one damage/Crystal/cooldown/destruction/event implementation. Unit attackers preserve their old ordering and behavior; scrub hidden/dead attackers to one absent identity without leaking their original kind.
- On turret construction completion, insert `AttackCooldown` beside existing `Dropoff`/`ProductionQueue` grants; unfinished sites have no attacker component. In the existing combat step, process tower attackers deterministically using the already-built acquisition snapshot and **extend existing `acquire_target` with a range argument rather than forking selection**. Filter by Team-1 ownership, enemy-alien kind, current visibility, range and cooldown. For a turret, measure each candidate's distance from **`Footprint::closest_point(target_position)`**, not the footprint center; adapt the common distance calculation minimally for unit-position vs building-footprint attackers. Order by distance then stable ID, with no movement or persistent target orders.
- Extend bridge attacker visibility filtering and event serialization with `attacker_kind`, reusing the existing `CombatTarget` kind/id match and cell-or-footprint visibility rules. Invisible/dead attacker IDs and kinds remain scrubbed. Update the controller to resolve the corresponding existing unit/building view; place tracer origin at the tower view while the **authoritative range** uses the nearest footprint point. Reuse `CombatFx` tracer and cue. Do not add new SFX.
- Tests: incomplete/complete tower (no `AttackCooldown` before completion), **2×2 closest-point range boundary** vs center, cooldown/visibility/Spitter counter, turret kill Crystal credit once, reused `CombatTarget` unit/building attacker event payload, no hidden **kind or ID** leak, and unchanged unit-kill/Result behavior.

### 4. Alien reachable-structure fallback

**Files:** `combat.rs`, `waves.rs` only where retry ownership belongs, `commands.rs` approach-slot helper reuse, tests.

- Detect a core dispatch rejected as `Unreachable` (or an existing core route that becomes unreachable after a map revision). Keep the current `waves.rs` one-second retry as scheduling upper bound; it is **not** adequate A* suppression by itself. Expose the existing `CommandResult` from `dispatch_attack_move` only as needed to observe rejection; no direct `CombatOrder::Attack` insertion. Maintain a minimal **per-alien failed-fallback revision marker** (patterned after `MoveOrder.last_failed_replan`). If reachability probes find no route to **any** player structure on the static map, store `map.revision()` and skip fallback/core A* for that alien until it changes. Clear on map revision change, successful assignment or reset/despawn. Do not cache temporary unit-slot reservation/crowding rejects as static failures. No per-tick structure/path scanning.
- Rank live Team-1 buildings (including construction sites) by distance from alien to footprint, then ID; probe reachable immediate-perimeter slots using existing `approach_slots` and team-aware A*. Send an ordinary **`AttackMove` to the selected reachable approach slot** through `dispatch_attack_move`, not a Direct Attack against an unseen building (the existing direct-attack visibility gate would reject or drop it). Existing 8-cell acquisition picks up a visible Wall/Gate on arrival, shared strike destroys it, and ordinary stranded retry then retasks survivors toward the core; **no separately stored pending core destination**. Preserve the current behavior that aliens also chew any other visible Wall/Gate near their route after a breach.
- Cover full wall ring, gate in ring, newly built barrier while moving, unreachable nearer site vs reachable farther site, destroyed fallback target, no reachable structure, deterministic ties, and **real fog**: seed/refesh `VisibilityMap` as `combat/tests.rs` does, keep distant fallback target initially unseen, verify that its `AttackMove` remains valid until acquisition, and never rely on fog-free pure-sim behavior. Confirm aliens can keep attacking **another structure** after a breach rather than requiring an immediate straight path to the core.
- **Mandatory sealed-out regression:** create 150 aliens with no reachable Team-1 structure, perform their first failed fallback probes, then simulate >=3 separate one-second retry boundaries at *unchanged* map revision and assert `GridMap::path_call_count()` does not increase; keep new wave launches/unrelated route work out of the measured interval. Bump the revision (e.g. destroy a gate) and verify probes resume and aliens recover. Focus on A* calls, not elapsed runtime.
- **Bounded siege pathfinding measurement:** with ~150 aliens marching/attacking a wall ring, record the **delta in `GridMap::path_call_count()` per one wall-placement or destruction revision bump**, with a clear initial unit census and observed delta. The existing 200-unit benchmark intentionally excludes defenses. Record the actual result; **do not invent a pass threshold or implement shared flood-fill caching before measuring**. If the measured churn demonstrates a practical bottleneck, scope the smallest fix inside this PR.

### 5. Fast build UX and automatic construction continuation

**Files:** `buildings.rs` (`step_construction` signature and completion), bridge fixed-step caller, `battlefield_controller.gd`, existing main-scene build grid and any placement tests.

- Extend step-construction's call to receive `GridMap`. After completion, choose candidate unfinished unassigned friendly sites sorted by distance/ID; use the existing `apply_resume_construction` validation/order install. One successful handoff; otherwise Idle. Do not add a global queue.
- Add build buttons/catalogue entry display for Wall, Gate, GunTurret and distinguishable primitives. Keep placement armed after successful Wall/Gate clicks only. Right-click while armed cancels (no contextual command); Esc cancels and does not pause. Ordinary buildings remain one-shot.
- Tests: two/three chained sites with last-placed active, completion follows nearest reachable old site, skips busy/blocked sites, and respects one-builder constraint and freeze/restart. **In stage 5, extend the existing `smoke_test.tscn` leg** with a small *real Godot input* assertion: Wall/Gate success leaves placement armed for a second click, right-click cancels without dispatching a contextual/move command, and Esc cancels before pause. Check the command-feedback revision/visible state so an accidental order does not pass unnoticed. This early smoke is required before the larger stage-6 defense journey, not a Rust-only UI test; retain existing HUD input shielding.

### 6. Integrated journeys, README and gates

**Files:** new `godot/scripts/defenses_smoke_test.gd` plus scene (or small focused extension of existing smoke), CI scene registration, `README.md`, targeted Rust system-order/bridge tests if necessary.

- Run a real Godot journey at accelerated sim speed with **authoritative fog**: arm/place a wall run, place Gate, human moves through, alien route rejects the Gate, turret fires/earns Crystals, sealed aliens `AttackMove` to/break a Gate (initially out of visibility) and then continue damaging **the core or other visible structures**. Do **not** require a straight sprint to the core after the breach: existing `AttackMove` attacks nearby walls. Allow labeled white-box setup only for remote-time/wave setup; keep ordinary command interfaces under test. Exit 0 with success marker, within existing 90s real-time smoke limits.
- Preserve existing bridge/reset/economy/combat/wave smokes; Start/Pause/Result/Restart, fog/minimap and 200-unit benchmark remain honest. Do not hide failures by disabling assertions or benchmarking static entities.
- Update README for wall/gate/turret controls and defense gameplay. Parent survival spec changes only if an approved design deviation occurs.
