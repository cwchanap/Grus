**Issue:** https://linear.app/cwchanap/issue/HPA-181/grus-survival-58-heat-and-cold-surface-efficiency

**Status:** Planning only, not implemented. **This draft PR becomes the implementation PR**. Keep one PR for HPA-181.

## Why this task and code survey

- Linear HPA-181 is now In Progress; its only blocker HPA-450 is Done and merged. HPA-181 unblocks HPA-188's research/tower milestone implementation. Art/SFX tickets stay separate.
- `catalog.rs` currently has seven `BuildingKind` variants and a `BuildingSpec` without heat fields. All costs, footprints and durations already use this catalogue. The one new Furnace fits the existing building path.
- `buildings.rs` handles validated placement, paid construction, builder handoff, completion, HP and ordinary destruction. No furnace-specific command is needed.
- `economy.rs::TeamEconomy` stores integer Coal in the shared Team-1 stockpile; `ResourceStockpile::try_spend` already enforces prices. Heat burning is the one new continuous-consumption path.
- `production.rs::step_production` tracks `progress_seconds` for the queue head, and `combat.rs::step_combat` ticks `AttackCooldown` globally before turret acquisition; modify only these rate multipliers. Turrets already use shared `strike`.
- `grus-godot/src/lib.rs::build_app` explicitly chains `apply_pending_commands → advance_waves → advance_combat → advance_movement → advance_economy → advance_construction → advance_production → advance_visibility → drain_route_reject_feedback`. `system_order.rs` covers its invariants.
- `GrusBridge.economy_snapshot` and `wave_snapshot` already feed `battlefield_controller.gd::_refresh_hud`. `main.tscn` has a 100px EconomyPanel and 3-column BuildGrid with six buttons; adding a furnace requires a small layout adjustment. `building_view.gd` already styles team colors and Gate parts share its material.
- The repository already has `defenses_smoke_test.gd` and CI hooks for sim coverage, headless smokes, Linux export/E2E and 200-unit benchmark. Extend rather than replace these contracts.

## Checkpoints on the same PR

The following are implementation stages **inside this single PR**, not separately tracked tickets or follow-up PRs. Keep the branch mergeable between stages where practical.

### 1. Catalogue, seed and heat computation

**Files:** `crates/grus-sim/src/{catalog.rs,heat.rs,lib.rs,fixture.rs}` plus `catalog/tests.rs` / new `heat/tests.rs`.

- Add `CoalFurnace` to `BuildingKind`, `ALL`, the existing `building_spec` match: 2×2, 80 Scrap, suggested 20s / 300HP. Add `heat_supply` and `heat_demand` to all building specs per design; all numeric tuning in the catalogue.
- Implement a single `HeatState` resource with supply, demand, efficiency and pooled fractional burn remainder. Count only complete Team-1 structures; check Coal before enabling completed furnaces; accumulate `completed_active_furnaces * 0.5 * seconds`, deduct whole Coal with float threshold tolerance, cap to available Coal and clear remainder on empty. All demand is catalogued. Compute formula with floor 0.25 and zero-demand 1.
- Add `step_heat(&mut World, seconds)` as a plain sim function. Skip mutable work when gameplay is not active, and initialize a zero-time snapshot at seeding; reset reinitializes both snapshot and burn remainder. Keep no additional fuel component or duplicate state in Godot.
- Scope tests to: starting 15/10; exact completed vs construction-site demand; zero-demand fallback; minimum floor; one and two furnaces at 20 Hz with exact 2s/1s whole-Coal consumption; depletion and next-tick output drop; refuel after empty; multiple producers; pause/result no changes; restart resets remainder. Include building destroyed/unfinished transitions.

### 2. Fixed-step integration and controlled rates

**Files:** `crates/grus-godot/src/lib.rs`, `crates/grus-sim/src/{production.rs,combat.rs}` and tests, `crates/grus-sim/tests/system_order.rs`.

- Add `advance_heat` after `advance_waves` and before `advance_combat` in the existing `FixedUpdate` tuple. Both `combat` and `production` consume the current tick's `HeatState.efficiency`. Update `system_order.rs` with a same-tick cold-rate regression and keep existing movement/gather/construction ordering unchanged.
- Apply `seconds * efficiency` only to surface producer queue-head progress. Keep all queue completion/population/blocked-spawn logic intact, and ensure already-at-100% jobs aren't penalized by a subsequent heat deficit. When `HeatState` is missing, both production and combat read `world.get_resource::<HeatState>().map_or(1.0, |h| h.efficiency)` to preserve existing directly seeded test worlds.
- In `step_combat`, tick `AttackCooldown` for unit attackers at the previous full speed but turret/building attackers at the scaled rate. The same `strike` installs the nominal cooldown; do not double-scale the duration on strike or damage. Ensure unfinished turret and alien unit paths remain unchanged.
- Tests: two equivalent fixed-step sequences at 100% vs 50% efficiency for queue/turret output, plus rapid warm↔cold transitions (remaining cooldown tracks elapsed effective seconds); prove workers, unit attacks, worker gather and construction times unaffected. Include direct production and turret tests with **no `HeatState` resource**, asserting full-rate behavior without a panic. Use deterministic tick counts; no timing sleeps.

### 3. Bridge, HUD, building view and furnace control

**Files:** `crates/grus-godot/src/lib.rs`, `godot/scripts/{battlefield_controller,building_view}.gd`, `godot/scenes/main.tscn`, existing bridge tests.

- Expose read-only `heat_snapshot` with supply, demand and efficiency. Update the Rust catalogue payload and parser test for `CoalFurnace`, and add the new BuildGrid button. Reuse existing placement preview/command/transaction and construction completion; no new input mode.
- Add a Heat label and use the same snapshot to update a short HUD string and each current friendly completed building view. Provide a view method that switches from Team 1's normal saturated blue to a **clearly different desaturated/whitened icy tint** (not another similar blue), including Gate parts; late-attached views must inherit the live tint. Verify visibility of the difference and restoration on rewarming in the smoke. Keep health bars and fog view visibility unaffected.
- Widen/stack the existing EconomyPanel and Shift SelectionPanel/BuildGrid as needed so the added Heat line, idle-worker button and seventh build option remain visible at 1280×720. Do not hardcode price, heat or footprint data in GDScript. The Coal Furnace may use a simple primitive body.
- Bridge tests verify snapshot field types/value semantics and parser exact names. Godot input smoke verifies the Furnace button, cost tooltip, placement and completion through the normal real bridge, not a direct world mutation.

### 4. End-to-end regression, docs and evidence

**Files:** `godot/scripts/heat_smoke_test.gd` + `godot/scenes/heat_smoke_test.tscn`, `.github/workflows/ci.yml`, `README.md` and focused tests.

- Run a real headless Godot scenario: Start; build Furnace and verify its heat + Coal burn; build enough completed structures to incur a deficit; assert the HUD and cold visuals; compare one turret and one Barracks/Research Center at cold vs warm at controlled sim time; pause (no burn/cooldown/queue advance); exhaust Coal; regain Coal via normal gathering or a test fixture state where necessary; restart to baseline. Use existing command/input and smoke helpers; do not handwave simulation correctness with mocks.
- Add the scene to CI with a bounded timeout and a unique `GRUS_HEAT_SMOKE_OK` success sentinel. Include it in failure postmortem reruns if CI convention requires. Existing smokes must still pass.
- Extend README's actual supported structures, construction actions and HUD docs with heat formula and cold exemptions. Keep `CLAUDE.md`'s current chain description synchronized if it is still used as repository guidance; document any observed baseline changes, not invented results.
- Verify Rust tests, clippy, formatting, 90% sim line coverage, headless smokes, export E2E and unchanged 200-unit benchmark. **Do not** invent passing CI, benchmark metrics or full-game playtest evidence while this PR is still planning-only.

## Explicit acceptance checklist

- [ ] No extra framework, persistent heat currency or separate tower engine introduced
- [ ] New Furnace placed and completed through the same Worker construction path
- [ ] Supply/demand derive from completed surface buildings and catalogue only; floor/zero demand correct
- [ ] Fractional Coal burn deterministic, halts on empty stockpile, restarts on refuel
- [ ] Cold slows only surface production and completed tower attack frequency, not units/economy/construction
- [ ] Heat refresh is ordered after waves, before combat and production; same-tick effects tested
- [ ] UI shows Heat supply/demand/efficiency and visible cold tint, reverting at normal efficiency
- [ ] Pause/Result/Start burn nothing; restart/benchmark seed state correct
- [ ] Rust format, Clippy, tests, ≥90% line coverage and existing + new Godot smokes green
- [ ] Linux export/E2E and survival benchmark verified or evidence explicitly flags unavailable gates
- [ ] Final implementation, tests, docs and review fixes all land **in this PR**
